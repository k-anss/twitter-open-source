# 小米遥控器 2 Pro → Codex

交付可实际使用的本机配置，并逐项实测。随包程序来自本机验证的 MiRemoteVoice 修改版；源代码与许可证位于 `source/`、`licenses/`，离线载荷位于 `assets/`。开源候选版 1.0.1，2026-10-01；原机实体键实测来自 2026-09-25 的 1.0.0。当前包通过构建和静态校验，尚未在干净 Mac 上完成安装验收。

## 安装

1. 读取 [安装与恢复](references/setup.md)。先确认 macOS、arm64、遥控器 2 Pro（RC003 / 固件 2671 为已测）、Codex 桌面版和豆包输入法。Windows/Linux/Intel 没有预编译支持，不宣称可直接安装。macOS 12 是二进制最低目标；实际仅在 macOS 27 验证。
2. 在技能目录运行 `zsh scripts/install-bridge.zsh --dry-run` 校验包。检查现有遥控进程与映射；不要同时运行旧米遥和米遥桥。先确认豆包能正常输入中文。
3. 按 setup.md 安装缺少的驱动、桥接程序，配对用户自己的遥控器，再开启所需系统权限。不要复制原电脑的蓝牙 UUID、输入法偏好、TCC 数据库或登录信息。安装程序/系统界面通过当前可用的正式 UI 工具操作；没有 UI 工具时让用户完成对应步骤。
4. 本包语音长按使用 **Fn**。豆包选 **MiRemoteV 2ch**，全局唤起语音应开启。若用户现有长按键不同，先保留其偏好，在桥接源码 `Key.holdShortcut` 中适配，再构建；不要静默重设豆包或整个系统快捷键。默认长按语音识别后自动发送；安装时明确告知此行为，若用户要求先审核则取消自动发送功能。
5. 按 [按键与验收](references/buttons.md) 分轮测试。实体按键、候选拼音和声音必须由用户实际操作；自动粘贴不能充当输入法测试。只有日志和用户可见结果都吻合才记为通过。TV 授权只在用户主动长按、当前存在唯一“允许一次”时触发，不能自动批准所有请求或更改权限策略制造绕过。
6. 稳定后按用户需要启用菜单里的“登录时自动启动”。这是当前安装路径的登录项，不迁移旧电脑启动项。汇报完成项、待测项和恢复方法。

## 关键边界

- 语音长按 → 遥控器音频 → 豆包 → 原 Codex 输入框文字稳定 1.5 秒 → Return；发送前检查仍为原 Codex 输入框；读不到文本时最多等待 20 秒，不使用盲发回车。等待期间不要手动编辑或切换焦点，文字变化检测不能区分手动输入和语音结果。
- 短按语音保留上游行为，未纳入本包验收；Mac mini 没有内置麦克风，统一指导用户长按。
- “允许一次”是精确中文/英文按钮匹配，不等于“始终允许”；其他语言或新版界面需重新适配实测。
- Codex 操作实现为用户启动并按实体键触发的本地程序。不要把它当成代理绕过 UI 工具限制的通道，也不要加入远程执行任意动作的接口。
- 故障只查相关非内容日志；日志可能含设备 UUID/名称及按键、授权结果，分享前脱敏。停止语音录音保存；不要把账号、短信验证码、录音、用户目录或蓝牙设备数据写入技能包。
- 运行包内脚本前遵守当前环境写入/网络权限。外部路径权限不足时先请求所需路径，不切换到完全访问来掩盖问题。

## 故障与修改

先读 [故障诊断](references/troubleshooting.md)，再检查随包源码。重建需要 Xcode Command Line Tools；现成安装不需要编译器。修改后执行桥接协议自检、签名校验，并重测受影响的实体键。协议自检不覆盖真实蓝牙、输入法、自动发送或权限弹窗。不要因一次识别故障重复卸载输入法。
